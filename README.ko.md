# Dolmen

[English](README.md) | 한국어

스키마 버전관리가 내장된 오픈소스 AI 네이티브 데이터베이스 클라이언트입니다.

> **상태:** 초기 미리보기입니다. macOS, Windows, Linux용 빌드는 [Releases](https://github.com/whalebanana86/ai-dolmen/releases)에 올라갑니다.

*돌멘(dolmen)* 은 "돌 테이블"이라는 뜻의 고인돌로, 수천 년을 버텨 온 거석 유적입니다. Dolmen이 만들어지는 한반도에는 전 세계 고인돌의 약 40%가 있습니다. Dolmen은 여러분의 테이블 이력도 그만큼 오래 남게 하려 합니다. 모든 스키마 변경이 Git에 기록됩니다.

## 설치

[Releases](https://github.com/whalebanana86/ai-dolmen/releases)에서 플랫폼에
맞는 설치 파일을 받으세요. macOS는 `.dmg`(Apple 실리콘은 `aarch64`, Intel은
`x64`), Windows는 `-setup.exe`나 `.msi`, Linux는 `.AppImage`, `.deb`, `.rpm`입니다.

아직 알려진 개발자의 서명이 없습니다. macOS가 앱을 확인할 수 없다고 하면
*시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기*로 열거나,
`xattr -dr com.apple.quarantine /Applications/Dolmen.app`을 한 번 실행하세요.
Windows에서 SmartScreen이 막으면 *추가 정보 → 실행*을 고르세요.

업데이트는 *설정(⚙) → 업데이트 → 업데이트 확인*에서 합니다. 프로젝트 키로 서명된
새 릴리스만 설치한 뒤 다시 시작하며, 확인을 누를 때만 새 버전을 찾습니다.
Linux에서 `.deb`나 `.rpm`으로 설치했다면 업데이트를 설치할 때 관리자 암호를
묻습니다.

## 계획된 기능

- **Git 기반 스키마 버전관리** — GUI나 SQL 에디터에서 바꾼 내용을 읽기 쉬운 스키마 스냅샷과 마이그레이션 파일로 만들어 저장소에 커밋합니다. 데이터베이스가 저장소와 어긋나면 드리프트로 알려 줍니다.
- **데이터를 이해하는 AI** — 스키마를 아는 자연어→SQL 변환, 쿼리 설명, 에러 수정을 사용자 본인의 API 키로 제공합니다. 스키마와 그 Git 이력, 코드베이스를 컨텍스트로 씁니다.
- **기본이 안전** — AI가 만든 쿼리는 읽기 전용으로 실행하고, 변경은 실행 전에 영향을 보여 주며, 운영 연결은 보호됩니다.
- **깊이** — 실행 계획 시각화와 성능 진단.

## 스키마 스냅샷

Dolmen은 데이터베이스 구조를 객체 하나당 DDL 파일 하나로 폴더에 씁니다
(`public/tables/users.sql`, `public/views/…`, `functions/`, `types/`). 그래서 코드
옆에서 Git으로 관리할 수 있습니다. 앱의 **Snapshot**은 마지막 스냅샷 이후 바뀐 내용을
보여 주고, 파일을 쓰고, 커밋하고 푸시합니다. **History**는 저장소 그래프를 그리고 아무
커밋이나 태그를 데이터베이스와 비교합니다.

코드를 체크아웃하듯 반대 방향도 됩니다. 스냅샷 패널에서 브랜치를 바꾸거나, **History**에서
커밋이나 태그를 고르거나, Git으로 체크아웃한 뒤 **Changes**를 열고 **Update database**를
누르면 *로컬* 데이터베이스를 그 시점에 맞추는 DDL 계획을 보여 줍니다. 계획은 한 트랜잭션으로 실행되어 전부 적용되거나 전혀
적용되지 않습니다. 데이터를 지우거나 컬럼 타입을 바꾸는 단계는 직접 허용하기 전까지 막혀
있고, 이름 변경으로 보이는 삭제는 이름 변경으로 적용해 데이터를 지킬 수 있습니다. 이를 위해
각 스냅샷은 만들어진 시점의 스키마 모델을 `dolmen-model.json`에 함께 저장합니다.

같은 비교를 명령줄에서도, 예를 들어 CI에서 실행할 수 있습니다.

```sh
cargo install --git https://github.com/whalebanana86/ai-dolmen dolmen-cli

dolmen schema dump  --url postgres://user@host/db --dir db/schema   # 스냅샷 쓰기
dolmen schema check --url postgres://user@host/db --dir db/schema   # 비교
```

`check`는 일치하면 0, 다르면(드리프트) 1, 오류면 2로 끝납니다. `--url`이 없으면
`DATABASE_URL`을, 비밀번호가 없으면 `PGPASSWORD`를 씁니다.

```yaml
# .github/workflows/schema.yml
- name: 운영 DB가 db/schema와 어긋나면 실패
  run: dolmen schema check --dir db/schema
  env:
    DATABASE_URL: ${{ secrets.DATABASE_URL }}
```

## 상세, 관계, ERD

테이블, 뷰, 함수를 오른쪽 클릭하고 **상세 보기**를 고르면 컬럼, 키, 제약 조건, 인덱스,
DDL을 볼 수 있습니다. 테이블 상세에는 그 테이블이 참조하는 테이블과 그 테이블을 참조하는
테이블이 ON DELETE, ON UPDATE 규칙과 함께 나옵니다. **ERD**는 스키마의 테이블과 외래 키를
다이어그램으로 보여 주고, 테이블 하나와 바로 연결된 테이블만 볼 수도 있습니다.

스키마, 그룹, 객체를 오른쪽 클릭하면 **새 테이블…**, **새 뷰…**, **새 함수…**로 같은 방식으로
작성하고 검토해 만들 수 있습니다. 상세의 **수정**으로 테이블(이름, 컬럼, 제약 조건, 인덱스, 주석), 뷰의 쿼리, 함수의 정의를
바꿀 수 있습니다. Dolmen이 실행할 문장을 먼저 보여 주고, 문장은 한 트랜잭션으로 실행됩니다.
데이터를 잃을 수 있는 단계는 직접 허용해야 하고, 실행 대신 편집기에 넣을 수도 있습니다.

## 쿼리 히스토리

편집기는 탭(⌘T)으로 여러 개를 열 수 있고, 탭마다 자기 세션을 써서 트랜잭션·search_path·취소가
서로 섞이지 않습니다. 탭 옆의 스키마 선택에서 현재 탭이 스키마 없이 쓴 이름을 찾을 스키마 하나를 보고 바꿀 수 있습니다.
다른 스키마의 테이블은 `public.users`처럼 스키마를 붙여 씁니다.

**히스토리**(⌘⇧H)에는 연결마다 실행한 문장이 최신순으로 나오며, 검색·별표·편집기에 넣기·
다시 실행을 할 수 있습니다. 앱에서 적용한 수정과 스냅샷도 함께 남습니다. 이 컴퓨터의
SQLite 파일(본인만 읽기 가능)에만 보관하고, 90일 동안 연결당 최대 1만 건을 남기며(별표한
쿼리는 지울 때까지), 비밀번호와 연결 비밀 값은 가리고, 결과 행은 저장하지 않습니다. 운영 DB처럼
SQL을 남기면 안 되는 연결은 연결별로 끌 수 있습니다. 편집기 내용도 연결별로 저장됩니다.

## 데이터 편집

결과의 행이 테이블 하나에서 왔고 그 테이블의 기본 키가 들어 있으면 그리드에서 바로 바꿀 수
있습니다. 셀을 더블클릭하거나 Enter를 누르면 편집하고(Shift+Enter는 줄바꿈, Tab은 다음
컬럼), **행 추가**로 새 행을 넣고, ⌘⌫나 오른쪽 클릭 메뉴로 행을 지우거나 값을 NULL로 바꿉니다.
변경은 그리드에 표시된 채 **저장**(⌘S)을 누를 때까지 기다리며, **SQL 보기**로 실행할 문장을
먼저 볼 수 있습니다. 저장은 기본 키로 행을 찾아 한 트랜잭션으로 하고, 바꾼 셀이 읽었을 때 값
그대로일 때만 합니다. 그사이 누가 행을 바꾸거나 지웠다면 아무것도 저장하지 않습니다. `BEGIN`으로
연 트랜잭션 안이면 그 트랜잭션에 합쳐져 COMMIT할 때 저장됩니다. 읽기 전용 연결에서는 편집할 수
없고, 운영 DB에서는 저장 전에 한 번 더 묻습니다.

## 데이터 가져오기·내보내기

테이블이나 뷰를 오른쪽 클릭해 **데이터 내보내기…**를 고르거나, 결과의 **내보내기…**를
누르면 모든 행을 CSV(원하면 Excel용 BOM 포함), JSON, `INSERT` 문으로 저장합니다. 결과를
내보낼 때는 그 문장을 읽기 전용 트랜잭션에서 다시 실행하므로, 화면에 보이는 행만이 아니라
모든 행이 저장됩니다.

테이블의 **데이터 가져오기…**는 CSV 파일의 행을 `COPY`로 한 트랜잭션 안에서 추가합니다.
파일은 UTF-8로 읽고, UTF-8이 아닌 파일은 글자가 깨진 채 들어가지 않게 막습니다. 한글
Excel이 EUC-KR(CP949)로 저장한 파일은 인코딩에서 EUC-KR을 고르면 읽습니다. 구분자는
알아서 찾고, 파일의 열을 테이블 컬럼에 이름으로 맞추며 일부는 건너뛸 수 있습니다. 잘못된 값이 있으면 몇 번째 줄 어느
열인지 알려 주고 아무것도 추가하지 않습니다.

## 운영 DB 보호

저장한 연결에 환경(개발, 스테이징, 운영)을 정하면 작업 화면 위쪽에 색 띠와
배지로 보입니다. 운영 연결은 **읽기 전용**으로 시작합니다. 툴바의 자물쇠로 쓰기를
허용하기 전까지 모든 탭의 세션이 데이터 변경을 거부하고, 운영에서는 자물쇠를 두 번
눌러야 풀립니다. 잠겨 있는 동안 상세 패널의 편집과 스냅샷 적용도 거부됩니다. 두
기본값은 연결마다 바꿀 수 있습니다.

`WHERE` 없는 `UPDATE`·`DELETE`, `TRUNCATE`, `DROP`, 컬럼 삭제는 실행하기 전에
어느 데이터베이스에서 문장마다 약 몇 행이 영향을 받는지 보여 주고 묻습니다.

## 실행 계획

**계획**(⌘E)은 커서가 있는 문장을 PostgreSQL이 어떻게 실행할지 보여 주고, ⌘⇧E는
`EXPLAIN ANALYZE`로 실제로 잽니다. 단계마다 행 수(실제와 예상), 그 단계가 직접 쓴
시간과 전체 중 비중을 보여 주고, 느린 쿼리의 흔한 원인을 짚어 줍니다. 대부분의 행을
버리는 순차 스캔, 열 배 넘게 틀린 예상, 디스크로 넘친 정렬 같은 것들입니다. 측정은
별도 세션에서 롤백되는 트랜잭션 안에서 실행하고, 데이터를 바꾸는 문장은 측정하기
전에 묻습니다.

## AI

AI 기능은 당분간 릴리스에서 빠져 있습니다. 써 보려면 `app`에서
`VITE_DOLMEN_AI=1 pnpm tauri dev`로 개발 빌드를 실행하세요.

편집기에서 **AI**(⌘K)를 누르면 Claude에게 평범한 말로 요청해 SQL을 받거나, 선택한
SQL의 설명을 들을 수 있습니다. 문장이 실패하면 **AI로 고치기**가 고친 문장을 제안하고,
실패한 문장을 그것으로 바꿀 수 있습니다. 요청에는 데이터베이스 구조가 스키마 스냅샷의
DDL과 주석 그대로 담기므로, 답은 실제 테이블과 주석에 적어 둔 의미를 따릅니다.

본인의 [Anthropic API 키](https://platform.claude.com/)를 씁니다. 설정(⚙)에서 넣으면 OS
키체인에 저장되고, `ANTHROPIC_API_KEY` 환경 변수도 쓸 수 있습니다. 기본 모델은 Claude
Opus 5.5이고, Sonnet 5.5와 Haiku 5.5는 더 빠르고 저렴합니다. Dolmen은 AI가 쓴 SQL을
스스로 실행하지 않고, AI를 위해 테이블의 행을 읽지도 않습니다. 다만 물어본 SQL과 오류
메시지 안의 값은 스키마와 함께 전송됩니다.

## 개발

준비물:

- Rust (stable)
- Node.js 20.19+ 또는 22.12+
- pnpm 9
- 플랫폼별 [Tauri 시스템 의존성](https://tauri.app/start/prerequisites/)

```sh
# 데스크톱 앱
cd app
pnpm install
pnpm tauri dev

# CLI
cargo run -p dolmen-cli -- --help
```

개발·테스트용 로컬 PostgreSQL (Docker 필요):

```sh
docker compose up -d   # localhost:55432에 PostgreSQL 18, 사용자·비밀번호 "postgres"
DOLMEN_TEST_PG_HOST=localhost DOLMEN_TEST_PG_PORT=55432 cargo test
```

`DOLMEN_TEST_PG_HOST`가 없으면 서버가 필요한 테스트는 건너뜁니다.

릴리스하려면 `Cargo.toml`(`[workspace.package]`)과 `app/package.json`의 버전을
정해 커밋하고, `v0.2.0`처럼 같은 버전의 태그를 푸시하세요.
[Release 워크플로](.github/workflows/release.yml)가 설치 파일을 빌드해 릴리스에
붙이고, 모든 플랫폼의 설치 파일과 업데이트 파일이 올라가면 공개합니다. 워크플로에 적힌
Apple 시크릿이 있으면 macOS 앱을 서명하고 공증합니다.

업데이트 파일은 `TAURI_SIGNING_PRIVATE_KEY` 시크릿의 개인 키로 서명하고, 설치된 앱은
그 키로 서명된 업데이트만 받습니다. 공개 키는 `app/src-tauri/tauri.conf.json`에
있습니다. 개인 키를 잃거나 바꾸면 이미 설치된 앱이 더는 업데이트되지 않으니 안전하게
보관하세요. 로컬에서 릴리스를 빌드하려면 `TAURI_SIGNING_PRIVATE_KEY`에 키나 그 경로를
넣고 `app`에서 `pnpm tauri build`를 실행하세요.
